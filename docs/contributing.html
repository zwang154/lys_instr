Contributing

Bug Reports

We use GitHub Issues to track public bug reports.

When opening a new issue, please include enough information for others to reproduce and understand the problem. Useful details include:

  • A short summary of the problem

  • Steps to reproduce the behavior

  • What you expected to happen

  • What actually happened

  • Any additional notes, such as possible causes, related error messages, or approaches you already tried

Pull Requests

Pull requests are welcome and are the preferred way to propose changes to the code.

Before opening a pull request, please check the following:

  • Fork the repository and create your branch from main.

  • Make sure your code follows PEP 8. We recommend using autopep8 or a similar formatter.

  • Add tests when your change introduces new behavior or fixes a bug.

  • Make sure the automated tests pass.

  • Update the documentation if you change public APIs or user-facing behavior. The documentation is written with Sphinx and reStructuredText.

  • Open the pull request on GitHub and briefly describe what the change does and why it is useful.

Testing

See Testing for instructions on running automated tests for core components and manual checks for GUI components.
